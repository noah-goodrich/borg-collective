# borg_core/compass/ rules

Rules owned by this directory, moved verbatim from the top-level CLAUDE.md.

- **The compass reader (`borg_core/compass/`) puts the owner's plain-file map on the `borg link --json` wire, additively, and forks nothing**: `core.py` is pure (text in, dicts out, on the clean-arch Domain list, import roots pinned by AST walk in `test_core.py`) and `shell.py` reads the files. The map directory is `$BORG_MAP_DIR`, default `$HOME/dev/map` (`paths.map_dir()`; `borg.zsh`'s `_borg_py` hands the variable down bare, a blank value means unset). The block is the top-level `compass` key, on `--json` and on the human page's document (not `--porcelain`, not the unregistered-directory hint page), in every scope: `{"found": false, "map_dir": ...}` and nothing else when the directory holds none of `log/`, `destinations/`, `README.md`, `parking-lot.md`; otherwise the leg, each destination with its state (`done`/`killed`/`frozen`/`proposed`, else `undated`/`late`/`at-risk`/`on-track`), the parking lot with a `due` flag, and each registry repository's destination and `on_leg`. **A destination carries two dates and both count**: `due` is the NEXT WAYPOINT's date (the README.md destinations table's date column, joined in by `build_compass`) and `target` is the end date of the WHOLE destination (the `target:` line of the destination file's frontmatter: an ISO date, or TBD, or absent; TBD and absent are null, any other text is null plus one `warnings` entry naming the file and the value). `nearest_due` is the earlier of the two as an ISO string (null when neither is a date), and it is the date the rules read: an active destination with no `nearest_due` is `undated`, one before today is `late` (so a past target is late even while the waypoint date is ahead), one within 7 days with the next waypoint not complete is `at-risk`, else `on-track`, and `leg_priority`'s bucket 1 orders by it (a destination with only a target ranks there, not in bucket 2). `due` itself is unchanged, and `target` keeps its wire name but is now a date string or null where it once carried the raw text (TBD read as `"TBD"`). Every file is optional and a malformed one is skipped with a `warnings` entry, never an error. `DOCUMENT_VERSION` stays 2, `--porcelain` reads no map, and `today` comes from the document's one epoch (`shell.today_from_epoch`), never a clock read inside the reader. `borg_core/conftest.py` points `BORG_MAP_DIR` at a missing directory for every pytest so no test reads a real map. Nothing from a real map is ever committed here: fixtures are synthetic. **The page and `borg next` render it (render step)**: IN FOCUS carries `Compass: <leg> · on track N · at risk N · late N · undated N` in the Queen's scope (zero buckets omitted), `Compass: <leg>` plus `off route: <repository> is not on today's leg` on a repository's page (only when a leg was chosen, judged by the directory's own name and the repository it is a worktree of), and exactly `Compass: no map at <map_dir>` when `found` is false; each mapped Queen board row carries its destination's state (`· late`, `· on track`, `· off leg`...) right after the route cells and BEFORE the summary, which is cut (`...`) or dropped first so the row stays within `max(90, widest row without suffixes)`, never wrapped, so the widest rows keep theirs (`render._row_tail`); THE SUFFIX IS NEVER DROPPED: when a row's head plus its suffix is wider than that budget (the name column is shared, so one 60-character repository name does it to every row) the budget grows to the widest head plus suffix, and a board whose rows already fit keeps its bytes; WAITING ON YOU lists due parking items (`parking: <text> (look again <date>, seen N)`, Queen's page only, capped at 5). `borg next` sorts by `compass.core.leg_priority` first (today's leg, nearest `nearest_due` date, undated, then frozen/done/unmapped) through `nextpick.core.rank`; the non-interactive paths ask `python -m borg_core.nextpick.cli --top N` so they cannot disagree with the chooser, and the zsh jq pipeline that used to be the whole ranking survives only as the fallback when `--top` exits non-zero. A pinned repository off the leg therefore ranks below an unpinned one on it. `render.py` stays pure: the block arrives on the document.
