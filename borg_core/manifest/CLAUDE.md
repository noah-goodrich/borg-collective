# borg_core/manifest/ rules

Rules owned by this directory, moved verbatim from the top-level CLAUDE.md.

- **Manifests are read from ONE root: `<repo>/.stacks/`** (the contract step of the chain -> stack rename, 2026-10-14). `<repo>/.borg/chains/` and the older `<repo>/.borg/programs/` are no longer read, and `--root borg` is refused by name. A repository that still holds `*.json` there gets a named warning (the repository and `borg stack migrate`) through the same channel an unreadable root uses, in `borg link` (`--json` and the page) and in `borg stack`'s sweep, never silence and never an empty `▸ STACKS` presented as the truth; the legacy manifest itself is never parsed. Detection is a directory listing with no fork, so the `--local` fork count is untouched. `scaffold` always creates in `.stacks/` and refuses by name when git ignores it (`placement.choose_scaffold_root`, facts from `shell.scaffold_root`); it prints `root: <folder> (<reason>)` after its `scaffolded:` line. `borg stack` is the sweep verb; `borg chain` and `borg program` die pointing at it, and `--chains-dir` and `--programs-dir` are refused by name. An in-place edit writes back to the file it found, there is only one root so nothing is read twice (`manifest_roots` returns `.stacks/` or nothing), and an unreadable root or parent is a named warning, never silence. `merge-tree/coordinator.py` reads through `borg_core.manifest`, and `borg stack sync` rewrites a `.stacks/` manifest in place.
