## Key Findings

- Thesis in the talk's own words: software fundamentals matter now more than ever, because quickly producing code does not make code cheap.
- Practice list: shared design concept via sustained questioning (grilling), documented ubiquitous language, small-increment feedback (static types, browser, tests, TDD), deep modules with simple interfaces, and explicit human tracking of modules and interfaces.
- He reports from reading model thinking traces that shared terminology makes planning better and the model's reasoning less verbose, which is the basis for the glossary convention in the skills.
- Presents the skills as encodings of classic practice (DDD, Ousterhout, Pragmatic Programmer), not as a new methodology.
