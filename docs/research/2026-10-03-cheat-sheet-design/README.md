# How borg should communicate (directory name: cheat-sheet-design)

The directory slug names the question this research started with, whether one-page cheat sheets could help with project work. The run was re-scoped on 2026-10-04 to a broader question, how borg should communicate project information (status, priority, context, next moves) at the right time, in the right way and in the right amount. The current answer is v2; the slug stays so existing links keep working.

Status: the evidence half passes its citation gate; the design half is stamped NOT design-reviewed (three blind-review rounds each returned revise, and the run stopped at its ceiling). Updated 2026-10-07 against main at `b34e7e0`.

## Where to start

- `recommendation.md` is v2, the design: the glossary, the ELI10, the pick (Option E, Doorways), the five options, the council and the review rounds, and the prior-work catalogue. Start here.
- `analysis.md` is v2's evidence half: 13 principles, the six moments, and the source catalogue (98 cards, 93 included).
- `worked-examples.md` walks one day through all six moments under every option.
- `verification-report.md` is v2's citation check: 30 of 98 cards sampled, 0 failed, 3 inaccessible.
- `sources/` holds the 98 source cards. Snapshot pointers inside them name files that are not committed; re-derive each from the card URL.

## Archived

- `drafts/v1/` is the first run, framed around one-page cheat sheets. It is kept as a record and is not the current answer.
- `drafts/verification-report-v1-59cards.md` is v1's citation check over its 59 cards.
- `drafts/` also holds the curated search logs, the review packet and the paywalled-candidates list that fed v2.

## Not in this directory
