## Risks

- **Audit false-negatives.** Two scout claims were already wrong (presence, six-pager). Every removal
  must be re-verified against code before editing — do not apply the drift table blindly.
- **Version ambiguity.** `BORG_VERSION="v0.8.0"` but code comments reference v0.8.6+/v0.8.9. The true
  current release must be confirmed before stamping criterion 5, or the fix trades one wrong number
  for another.
- **`drone feature` assumption.** Two docs say `drone start`; the fix assumes `drone feature` is
  canonical — grep-confirm the exact subcommand name before mass-editing quickstart + cheatsheet.
- **Rot-proofing vs. readability.** Replacing inventories with `ls` pointers stops rot but removes the
  at-a-glance "what does each file do" value; decide per-file whether a pointer or a maintained
  annotated list is right (CLAUDE.md likely keeps annotations; architecture.md can point).
