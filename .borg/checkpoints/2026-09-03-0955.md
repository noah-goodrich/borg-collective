**The transferable lesson, and the reason this took five review rounds.** Three separate findings were the same defect
at successively higher altitudes: a guard whose own absence is indistinguishable from success. The floors had no oracle;
then two of four floors had none; then the oracle itself was inert in CI because the `test` job installed no Python and
a bats `skip` prints `ok`. Each fix introduced the next instance. **The tell is always the same: delete the guard and
every gate stays green.** Run that mutation on anything new that claims to gate something.

**Second lesson, about the method rather than the code.** Two of the five rounds' worst findings were doc-vs-tree
contradictions created by concurrent agents in the SAME round — one deleting the rc-5 arm and writing "MUST NOT BE
ADDED BACK", another writing "the arm stays as defence in depth" and assigning it a door. Never put a fact and its
description in two different agents' hands in one round. Round 6 was authored serially for that reason and produced no
new drift.

**Verification note:** five agents died across rounds 3 and 4 with "your computer went to sleep mid-response" — a local
suspend, not a usage limit, so the recovery is an immediate `Workflow({scriptPath, resumeFromRunId})` with no reset to
wait for. Round 3's script also reported a CRASHED review lens as CLEAN, because `agent()` returns `null` on terminal
error and the `.then()` mapped it to `{findings: []}`, which is truthy and survived `.filter(Boolean)`. Later scripts
report unrun lenses in a separate field. A check that did not execute must never be counted as a check that passed —
which is the same lesson as the floors, in the harness rather than the product.
