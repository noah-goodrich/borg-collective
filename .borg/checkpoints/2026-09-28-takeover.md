## Finding 2 — filename equality is not document equality, both ways
The retro surveyed one repo. There are **three** repo groups across 7 of 25 entries:

| group | colliding filenames | bodies |
|---|---|---|
| snowflake-permissions / -olf / -wt-e2e | 3 | all differ (`.borg/` gitignored) |
| borg-collective / -shim | 115 | 114 identical, 1 differs (`.borg/checkpoints/` tracked) |
| dbt / -csm_invoice_issue_agent_tool | 0 | — |

A union trusting filenames renders borg-collective's own page with 114 duplicate rows and pushes real
history off the top 3. So `dedupe_checkpoints` collapses by content digest — the rule
`manifest.shell._manifest_identity` already uses, for the same stated reason. Lazy and bounded:
charged only after a filename repeats, each row hashed once, walk stops at the cap. 0.116s → 0.135s
on the worst group, no new subprocess.

## §6.1 ruled — apex repo is home, other side resolves by slug
The binary was false. One authoritative copy in the apex's repo (no duplication); the second repo
reached BY REFERENCE, since rows already carry `owner/repo` and the apex is an issue number, making
`owner/repo#apex` a complete address. borg already computes `repository_slug()` wherever it stands —
what's missing is a resolver, not a copy. Only option consistent with §7's adapter rule. Q2–Q4 open.
