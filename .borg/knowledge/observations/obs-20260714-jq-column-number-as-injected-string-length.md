# obs-20260714-jq-column-number-as-injected-string-length

## content

When jq reports 'Invalid numeric literal at line 1, column N', and the JSON is generated by a shell script, column N-1 often equals the exact length of a string that was injected into the output stream before the JSON began (e.g., a CI hook path + ': line 3:' = 87 chars → column 88). Using the column number as a measuring tape to identify the injected string is a fast diagnostic shortcut.

## resolution

Compute len(suspected_injected_string) and compare to jq's column number minus 1. If they match, the injected string is the root cause of the parse failure, not the JSON logic.
